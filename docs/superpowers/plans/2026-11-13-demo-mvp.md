# Demo MVP — End-to-End Dispatch Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the PRD §6.8 loop (map → sync → code → lookup → route → failed outcome → re-survey task) run live on a fresh SQLite registry, the graph service and the Flutter app.

**Architecture:** Fix the four breaks in their real code paths: registry `push()` auto-issues codes and stores services; registry loads zones from a JSON file at startup; graph service projects lat/lon to local metres and can rebuild from the registry's breadcrumbs; the app sends a responder start point through `/v1/dispatch/lookup` and draws lat/lon route legs.

**Tech Stack:** Node 26 (`node:sqlite`, `node:test`), Python 3 + numpy/scipy/sklearn + pytest (`.venv`), Flutter/Dart (sqflite, http).

**Spec:** `docs/superpowers/specs/2026-11-13-demo-mvp-design.md`

## Global Constraints

- No new dependencies (npm, pip or pub).
- Registry runtime stays on `node:sqlite`; graph service stays on numpy/scipy/sklearn.
- Existing tests keep passing; each fix gets at least one test at its seam.
- Auto-issued codes use reviewer id exactly `system:no_nearby_structure`.
- A structure **with** a dedup candidate still gets no code until a human decides (C1/C2 unchanged for duplicates).
- Graph route `max_snap_m` (25) must be compared in real metres.
- Metre conversion constants match the registry: `x = (lon - lon0) * 111320 * cos(lat0 rad)`, `y = (lat - lat0) * 110540`.
- Before running Node tests: `cd services/registry-api && npm install` (the `qrcode` package is missing locally; 5 test files fail on import otherwise).
- Python: `.venv/Scripts/python -m pytest ...` from repo root.

## Review Focus

1. A rebuild from the registry with too few breadcrumbs (e.g. one 5-point walk) must answer `422 insufficient_breadcrumbs`, not crash with a 500 — this is the first thing that happens on demo day if the walk didn't sync. Test in Task 4.
2. A route request whose start or end is far off the network must still return `422 no_route` (the 25 m snap refusal), now in metres — not route to a node 25 *degrees* away. Test in Task 4.
3. Re-syncing the same structure op (replay) must return the same code, not mint a second one. Test in Task 1.
4. A structure op whose `services` contains an unknown `service_type` or a duplicate type must not lose the structure itself. Test in Task 2.
5. A missing or malformed `ZONES_FILE` must stop the server at startup with a clear error, not start with zero zones (which silently breaks every lookup). Test in Task 3.

**Interfaces:**
- Produces in `geo.py`:
  - `project(lat: float, lon: float, origin: tuple[float, float]) -> tuple[float, float]` and `unproject(x: float, y: float, origin) -> tuple[float, float]` (constants in Global Constraints).
  - `group_breadcrumbs(points: list[dict]) -> list[list[tuple[float, float]]]` — groups registry `/v1/breadcrumbs` rows by `trace_id`, orders by `seq`, returns `(lat, lon)` lists, drops traces with < 2 points.
  - `build_graph_latlon(traces: list[list[tuple[float, float]]], build_version: int) -> Graph` — origin = first point of first trace; projects every point; calls `hybrid.build_graph`; sets `graph.origin`. Raises `InsufficientBreadcrumbs` (defined in `geo.py`) when total points < 12 (the `adaptive_seeds` `kmin`).
- Produces in `hybrid.py`: `Graph.origin: tuple[float, float] | None = None`.
- Produces in `routing.py`: `route_latlon(graph, frm: dict, to: dict, **kw) -> Route` — projects `{lat, lon}` with `graph.origin`, calls `route`, then sets on each leg `from_latlon`/`to_latlon`. `Route.to_dict()` emits each leg's `"from": {"lat","lon"}` and `"to": {"lat","lon"}` when present. If `graph.origin is None`, behaves exactly like today's `route` (metric input).
- Server: `/v1/graph/route` uses `route_latlon`. `/v1/graph/rebuild` with body `{"source": "registry"}` fetches `$REGISTRY_URL/v1/breadcrumbs?limit=100000` (stdlib `urllib.request`), then `group_breadcrumbs` → `build_graph_latlon`. No `REGISTRY_URL` → `400 registry_url_not_configured`; `InsufficientBreadcrumbs` → `422 insufficient_breadcrumbs`. Body with `traces` keeps today's metric path.

def test_project_roundtrip_and_scale():
    o = (12.97, 77.59)
    x, y = project(12.97 + 0.001, 77.59 + 0.001, o)
    assert abs(y - 110.54) < 0.01
    assert abs(x - 111.32 * math.cos(math.radians(12.97))) < 0.01
    lat, lon = unproject(x, y, o)
    assert abs(lat - 12.971) < 1e-9 and abs(lon - 77.591) < 1e-9

def test_group_breadcrumbs_orders_and_drops_short():
    pts = [{"trace_id": "a", "seq": 1, "lat": 1.1, "lon": 2.1}, {"trace_id": "a", "seq": 0, "lat": 1.0, "lon": 2.0},
           {"trace_id": "b", "seq": 0, "lat": 5.0, "lon": 5.0}]
    assert group_breadcrumbs(pts) == [[(1.0, 2.0), (1.1, 2.1)]]

def _lane(lat0, lon0, n=60, step_m=2.0):
    # straight north-south walk, ~2 m spacing
    return [(lat0 + i * step_m / 110540, lon0) for i in range(n)]

def test_latlon_route_on_a_walked_lane():
    g = build_graph_latlon([_lane(12.97, 77.59), _lane(12.97, 77.59 + 1e-6)], build_version=1)
    r = route_latlon(g, {"lat": 12.97, "lon": 77.59}, {"lat": 12.97 + 100 / 110540, "lon": 77.59})
    assert r.reachable
    assert 80 < r.total_distance_m < 130
    d = r.to_dict()
    assert {"lat", "lon"} <= d["legs"][0]["from"].keys()

def test_far_destination_is_refused_in_metres():
    g = build_graph_latlon([_lane(12.97, 77.59)], build_version=1)
    r = route_latlon(g, {"lat": 12.97, "lon": 77.59}, {"lat": 12.97, "lon": 77.59 + 100 / 108500})  # ~100 m east
    assert not r.reachable
    assert any("outside_mapped_network" in w for w in r.warnings)

def test_too_few_breadcrumbs_raises():
    with pytest.raises(InsufficientBreadcrumbs):
        build_graph_latlon([_lane(12.97, 77.59, n=5)], build_version=1)
